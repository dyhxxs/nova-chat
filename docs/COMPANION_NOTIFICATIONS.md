# 陪伴消息通知（Agent27 工作区）

消息通知用于主动聊天、延迟回复和后台完成的照片。标题显示人设名字，正文显示消息预览或“[图片]”；点按后进入原账号、原服务器、原人设的具体话题。普通即时聊天回复仍由 WebSocket/生成任务收取，不单独投递系统推送。

## 当前可用范围

- 原生通知权限、Android 消息频道、前台提醒与点按跳转已实现。
- 陪伴消息现在按话题累计未读数：对话历史显示红色数字，角色列表显示该角色所有话题的汇总数字；打开话题后自动清零。App 图标角标也会跟随本地未读总数更新，最多显示 999，列表数字超过 99 显示为 99+。
- 正在看同一对话时不显示横幅或播放提示音；其他话题可以提醒。
- 未配置云凭据时，App 打开并收取服务端事件后可发本地通知。此模式不会在 App 已关闭时收取消息。
- 网关已实现 Expo 推送设备注册、持久发送队列、有限重试与无效令牌清理。退出登录、会话到期或账号禁用后停止为该会话发送。
- 工作区没有 EAS 项目 ID、Firebase 配置或 FCM/APNs 凭据；尚未完成真机后台通知验收。本次未部署或发布 APK，Agent26 下载包也不包含这些改动。
- Web 版当前不发送系统通知。

## 启用 Android 云推送

1. 在 Expo/EAS 建立本应用的项目，取得实际 project ID。将它写入 apps/mobile/app.json 的 expo.extra.eas.projectId，或在构建时注入 EXPO_PUBLIC_EAS_PROJECT_ID。代码也接受 EAS 构建提供的 Constants.easConfig.projectId。不要使用示例或随机 ID。
2. 在 Firebase 为现有包名 com.novachat.mobile 建立 Android 应用，下载对应的 google-services.json。通过本地受保护配置或构建环境提供此文件，并设置 expo.android.googleServicesFile 指向该文件；不要覆盖应用包名或签名。
3. 为该 EAS 项目配置 Firebase Cloud Messaging V1 的服务账号凭据。google-services.json 本身不等于 FCM 发送凭据；服务账号私钥通过 EAS 凭据管理提供，不放进 APK、仓库或文档。
4. 保留已经加入的 expo-notifications 插件，重新预构建并构建原生应用。仅更新 JavaScript 无法给旧 APK 安装缺少的原生模块。SDK57 的远程推送使用原生开发/发布构建验收，不使用 Expo Go。
5. 部署包含通知路由和 CompanionPushRuntime 的网关。如果 EAS 项目开启 Expo push access token 安全选项，在网关环境变量中设置 EXPO_ACCESS_TOKEN；此令牌只留在服务器。
6. 安装新包、登录并允许“陪伴消息”通知。App 会取得 ExpoPushToken，通过已登录会话 PUT /v1/companion-notifications/device 注册；设置页会显示云推送是否注册成功。

注册成功表示令牌已交给网关，不证明 FCM 已实际送达。Expo ticket 的 ok 也只是接收成功；当前发送器没有实现后续 receipt 查询，需通过真机检查实际提醒。

## iOS

使用同一 EAS 项目 ID，并为现有 bundle ID com.novachat.mobile 配置 Apple APNs 推送凭据，重新构建原生应用。iOS 用户需允许通知；临时授权也可收到系统允许的提醒。不要把 APNs 私钥打进应用或提交仓库。

## 验收步骤

1. 打开角色 A 的一个话题，让角色 B 的新主动消息或后台照片送达；确认角色 B 名字、预览和点按后的具体话题正确。
2. 保持在角色 B 的该话题，确认同一事件不重复提醒，读当前话题时不响铃。
3. 分别测试应用切到后台、进程不在运行时的通知及冷启动跳转。Android 用户主动“强行停止”会限制推送，需再次启动后验收正常后台状态。
4. 退出账号，再触发原账号消息；确认该设备不再收到旧账号推送。切换账号/服务器后点按旧提醒不得进入其他账号的对话。
5. 断网后恢复，检查消息不丢失、已成功投递的其他设备不会因单个设备失败而重复推送。服务端尝试最多三次；聊天事件始终保留供前台收取。

本地可运行 npm run verify、npm run build 和 Expo Android export 检查类型、回归与打包。上述检查不能代替原生通知权限、系统后台送达及软键盘行为的真机验收。
