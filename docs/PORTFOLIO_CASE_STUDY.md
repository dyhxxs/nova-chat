# Nova Chat 技术案例说明

## 案例主题

Nova Chat 解决的是一个具体的工程问题：用户希望在移动端使用不同的模型服务，同时保留自己的账户、对话和资料，并让模型供应商的密钥由服务端统一管理。项目以 React Native / Expo 客户端、Fastify Gateway、TypeScript 共享协议和 SQLite 为核心，支持自托管运行。

## 场景和边界

核心演示围绕“用户上传资料并获得带来源的回答”展开。角色照片、语音和图片生成是扩展能力。当前知识库使用 SQLite FTS5 词法检索 baseline；项目已提供合成评测集和可复现报告，混合检索、向量检索和大规模线上指标仍属于后续工作。

## 请求链路

```text
React Native App
  ├─ HTTPS：注册、登录、配置、文件和资料库
  └─ WSS：流式生成、取消和心跳
       ↓
Fastify Gateway
  ├─ Session / RBAC / 用户资料隔离
  ├─ 请求 ID、错误脱敏、限流和并发门
  ├─ SQLite：用户、Session、附件索引、资料库和模型配置
  └─ Provider Adapter
       ├─ Responses API
       └─ Chat Completions API
```

第三方 API Key 只在网关配置和运行时使用，数据库中使用 AES-256-GCM 保存。移动端只拿到自己的 Session Token；普通用户只能读取自己的资料和附件。

一次普通聊天请求会经历以下阶段：

1. 客户端生成稳定的 `requestId`，构建受预算限制的历史上下文；
2. Gateway 校验 Session、用户状态、模型白名单、请求格式、限流和并发额度；
3. 若启用资料库，Gateway 按当前用户检索最多 6 个来源片段，并把片段作为不可信数据传入模型上下文；
4. WebSocket 发送 `started`、`delta` 和 `done`；握手失败且尚未开始生成时使用 REST fallback；
5. 完成、取消或错误路径都会释放并发额度和任务状态；重复 Request ID 不会再次创建生成任务；
6. 客户端只把属于当前会话的结果写回本地历史。

## 关键设计取舍

### Gateway 保存模型 Key

让 App 直连模型服务会暴露 Key，也无法在多用户场景可靠实施白名单、审计、限流和用户隔离。Gateway 让供应商配置成为管理员控制面，用户只使用受权限保护的业务 API。

### WebSocket 和 REST 并存

WebSocket 适合流式增量输出、心跳和取消；REST 适合登录、上传、健康检查和握手失败时的 fallback。生成开始后不盲目自动重试，避免网络抖动造成重复调用和重复计费。

### SQLite FTS5 作为 baseline

单机自托管的资料库先采用 SQLite FTS5，依赖少、部署可复现、权限查询可以和业务数据库在同一事务边界内完成。中文 token 使用 Han bigram，英文、数字和代码术语按词处理；每份资料切成约 1200 字符片段，返回的来源带文档 ID、标题、片段序号和摘要。后续检索改进必须在同一评测集上比较，而不是凭感觉更换方案。

### 可验证的拒答

如果资料库模式没有命中足够的片段，网关直接返回本地拒答文本，不调用模型。命中的片段会以 `[资料1]` 等编号注入，并在指令中明确资料内容是不可信数据，不能覆盖系统规则、运行工具或泄露秘密。

## 企业级运行保障

当前 Gateway 已具备：

- `X-Request-ID` 请求关联；
- `/health`、`/healthz`、`/readyz` 三类运行检查；
- 可选 Token 保护的 Prometheus 指标；
- 登录失败按来源 IP + 邮箱限流；
- 日志对认证信息、Key、正文和工具指令脱敏；
- 用户、附件和知识库的所有者校验；
- 生产环境主密钥、管理员初始化 Token 和指标 Token 配置校验；
- Docker Compose 数据卷、备份和恢复验收说明。

这些措施改善了单机自托管的可运维性，但当前没有自动多副本共享限流、集中式日志、自动灾备、MFA 或大规模压测证据。项目把已经实现、已经自动化验证和仍需真实部署验证的内容分开记录。

## 验证方式

源码级验证入口：

```powershell
npm ci
npm run verify
npm run build
npm run knowledge:evaluate
```

知识库评测集是 80 条合成问题：40 条单文档问题、20 条跨文档问题、10 条应拒答问题和 10 条安全注入夹具问题。报告会写入 `artifacts/knowledge-evaluation/`，其中包含 JSON 原始结果和 Markdown 报告。延迟数字只说明当前 Node 进程中的合成检索表现，不代表生产 P95。

部署级验证还需要实际执行 Docker 启动、反向代理、模型连接、备份恢复和真机流式聊天；这些步骤不能由类型检查或单元测试替代。
