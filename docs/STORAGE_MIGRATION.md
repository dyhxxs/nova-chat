# 原生快照与凭据升级：迁移、恢复及回滚边界

适用：Nova Chat 1.1.27，以及从旧版 AsyncStorage 快照迁至 SQLite 的升级。它改变了本机原生存储格式，**不是仅 JS 热更新即可完成的升级**。expo-sqlite / expo-sharing 需要在原生壳中；分发前必须构建并验证同包升级与目标设备。

## 1. 升级前

1. 在旧客户端将各账号、各网关的聊天导出标准 Nova 对话 JSON；重要附件单独下载。
2. 若旧客户端支持独立助手备份，另行导出助手；否则把私有指令/开场草稿妥善保存。对话草稿不在标准聊天备份中。
3. 确认导出的文件可以解析且确实存在于应用沙盒之外。备份为明文，不要公开。
4. 在一次性测试账号、测试数据库及**相同测试 applicationId** 的旧版 → 新版安装包上演练；不能用新装独立包代替升级验收。
5. 不对真实数据库做故障注入，不以卸载应用、清除数据来“解决”迁移失败。

## 2. 新存储布局

| 内容 | Android/iOS | Web |
|---|---|---|
| 账户/网关历史、设置、助手、草稿 | nova-account-snapshots-v1.db，account_snapshots_v1 表，每范围一条原始 JSON | 原 AsyncStorage 适配 |
| 损坏恢复副本 | 同数据库，账户 key 的 /recovery 后缀 | 同原 AsyncStorage 范围 |
| 迁移前原文 | legacy_archives_v1 表，保留首次迁移输入 | 不迁移，无该档案 |
| 档案预览版本 | archive_revisions_v1 表，每账户持久递增 revision | 不提供跨标签页原子清理 |
| 连接 bootstrap | AsyncStorage，仅网关/设备元数据 | AsyncStorage |
| 登录 intent | AsyncStorage，仅 version/state/nonce，不含令牌或网关 | 同样无明文令牌回退 |
| 登录凭据 | SecureStore，version 2 envelope：token/serverUrl/nonce | 浏览器不支持安全存储时仅内存会话并告警 |

数据库不启用 SQLCipher，内容仍是明文；迁移档案会占额外磁盘空间，整体 JSON 解析仍受内存限制。并未实现逐消息增量 SQL、全文索引或附件二进制迁移。

## 3. 事务迁移顺序

1. 认证确定 userId 和网关后，按原账户 key 查询 SQLite。
2. SQLite 有活动记录时使用它；**不会因 SQLite 异常回退到 AsyncStorage 的旧副本**。
3. SQLite 无记录时读取原 AsyncStorage 字符串。若已存在迁移标记，或只有迁移档案而活动记录丢失，报错并禁止空白覆盖。
4. 对可读取的旧原文，在同一个 exclusive transaction 中插入档案和活动快照，并在事务中逐字核对两份内容，失败则回滚。
5. 提交成功后，才把旧值替换为 nova-chat:sqlite:v1 小标记，并检查标记确实保存。
6. 标记写失败仍会报错：原文已经在 SQLite 档案中，旧源未被提前删除。再次读取/登录会重试标记，不覆盖档案。新建账户的首次成功写入也建立标记。
7. 再交给已有 v7 快照验证/修复流程：过滤损坏记录之前必须成功保留原始恢复副本。归属或版本不对时不写回。

两种存储之间不是跨库分布式事务，磁盘损坏、两份存储同时丢失、在极端故障窗口外部删数据库都不在“保证恢复”范围内。旧 AsyncStorage 行如果已经大到无法读取，本轮不能自动提取出其内容；保留设备和应用数据，交由维护者在备份副本上排障。

## 4. 失败时怎么做

- **保存失败**：保留应用运行中的内容，导出当前聊天/助手，另存对话草稿；释放磁盘空间后重试。
- **读取被阻止**：不要继续把空白界面当成历史已被删除。保留新建内容后重登；仍失败时导出可读取的恢复/迁移原文，不公开发送。
- **迁移标记存在而数据库记录缺失**：客户端会保护性拒绝覆盖。不要手动删除标记；必须先在副本上核查数据库、WAL 和档案完整性。
- **凭据读失败**：全局提示可重试读取；不会删除账户历史。
- **凭据写失败**：当前登录可能仅存在于内存，重启需要重登；初始 intent 都失败时旧凭据还可能残留，务必重试。
- **退出部分失败**：退出 fence 或删除至少一个成功可阻止旧登录恢复，但仍显示清理提示；登录页也能重试。
- **退出两种保护都失败**：无法保证重启后仍退出，客户端明确警告。不要交出设备；存储恢复后重试，或从其他可信设备撤销该服务器会话。

原始档案不是标准备份，可能包含任意旧字段、配置与私人内容。不要承诺其绝不包含秘密。导出只检查当前账户范围及可解析时的 userId；严重损坏文本无法证明内部每个字段的归属。

## 5. 清空、卸载与降级

- “清空本地对话”只清空当前账号的对话列表；不删除助手、恢复/迁移档案、外部导出文件。不等于安全擦除。
- 退出保留本地历史。使用不同 applicationId 的测试包与正式应用沙盒互不相通，独立新装不能作为历史迁移通过的依据。
- **不要直接安装旧客户端覆盖新版。**旧版不了解 SQLite marker、助手来源字段和 version 2 凭据。旧版可能显示空历史/要求重登；降级后新写入的旧存储内容不会自动合并回 SQLite。
- 需要回退时，先用当前新版完整导出可移植文件并确认副本，再在隔离测试中验证目标旧版实际支持的格式。跨版本的原始数据库回滚必须由维护者按一致性副本处理；不提供“删除 SQLite/marker 即可无损回滚”的指引。
- 卸载/清除数据可能永久丢失聊天和档案；iOS 安全存储可能跨卸载残留，不能依赖卸载代替服务端会话撤销。

## 6. 保留档案维护（第三轮）

「数据与备份 → 存储检查与保留档案」按当前账户/网关列出活动快照、故障恢复副本、主快照迁移档案、恢复副本迁移档案的 UTF-8 正文大小。**这是逻辑文本量，不是数据库文件大小**；不含附件本体、索引、WAL、空闲页及外部文件。检查可能先迁移仍在旧存储中的恢复副本，避免漏计。

清理需要手动执行以下流程，不会后台自动触发：

1. 保留所需聊天 JSON、助手 JSON、草稿与必要的敏感原文；故障恢复区可分别导出本地恢复副本、迁移前原始快照、恢复副本的迁移原文。在应用之外确认文件真实可用。打开分享面板不等于备份完成。
2. 检查存储，点击「预览保留档案清理」。系统先等待当前快照保存完成；未登录、读取被阻止或保存失败时不给出可执行计划。
3. 阅读待移除的三类档案总量，并勾选已核实外部备份及接受永久移除。活动聊天、设置、助手和草稿不属于清理目标。
4. 确认时再次保存预览之后产生的当前内容，保存失败保留所有档案；重新校验账户/网关/会话 generation、读取状态及数据库中持久 revision；档案更新、重复确认或换账号会拒绝旧计划。
5. 在 exclusive transaction 中删除两种迁移档案，将恢复行置为空字符串，递增 revision 并验证结果。磁盘写/提交失败或事务中权限变化整体回滚。不删其他账户，不执行 VACUUM。

恢复行的空字符串是有意保留的 **tombstone**，不是未知丢失的记录。清理后仍保留迁移 marker；若直接删行，下次恢复写入会触发防丢失保护。重开数据库后空行与 revision 保持，新故障仍可创建新的恢复正文；活动快照意外缺失时仍拒绝空白覆盖。

只有显式清理会移除档案；正常保存不覆盖迁移原文，普通活动快照保存不递增档案 revision。迁移、写恢复副本及清理都会递增 revision。普通保存不再读回旧大 JSON，只读取新正文做写后验证，也不反复重写已正确的迁移 marker。

**清理不可撤销，但不等于安全擦除或磁盘立即缩小。**SQLite 空闲页、WAL、系统缓存及用户已有外部文件可能仍保留文本。Web 无可靠跨标签页原子删除协议，因此只提供统计，明确禁用清理，不把弱保护删除当成原生事务。

## 7. 已验证与未验证

- SQLite 测试使用 Node 内置 SQLite 执行真实 SQL 和事务，再通过 Expo async 接口形状适配到原生仓库；覆盖大于 6 MiB 输入、文件型数据库关闭/重开、回滚、提交失败、marker 失败、丢记录、并发、账号隔离；第三轮增加清理后关闭/重开、revision 失效、事务中换账号、写入/提交回滚、恢复 tombstone 再写及统计不复制正文。
- 集成测试显式将 store 路由到 snapshotStorage.native.ts，不以 Web fallback 的 Map 测试冒充原生 SQL 验证。
- 凭据测试覆盖写前/写后故障、nonce 不匹配、保存/退出竞态、双存储失败、重试与网关绑定。
- 通过三端 bundle 和 Android 原生构建，并检查 bundle 的平台选择；这**不是 Android/iOS 真机 SecureStore/SQLite 驱动验收**。
- 发布前仍须执行 [人工 QA 清单](QA_CHECKLIST.md)，尤其相同 applicationId 的升级/强制关闭/重启场景。
