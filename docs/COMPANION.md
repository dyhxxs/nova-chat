# 陪伴、人设与模型配置

Nova 的 AI 陪伴拥有独立角色资料和聊天界面。普通聊天继续保留完整模型与工具设置，陪伴界面把重点放在角色和对话上。

## 创建自己的角色

打开聊天页的 AI 陪伴入口，选择 Lumi，或新建角色。可编辑：

| 字段 | 用途 |
| --- | --- |
| 名字与对你的称呼 | 确定双方在对话中的称呼 |
| 性格 | 写清人物背景、具体偏好、习惯与边界 |
| 说话方式 | 决定句子长度、语气和常用表达 |
| 长相 | 上传参考照片，并填写可选的外貌描述 |
| 记忆 | 手动录入你允许角色使用的长期背景，并选择是否启用 |

性格与说话方式更适合用具体的日常细节来写。例如“课多时不太想说话，喜欢逛旧书店”，通常比堆叠“温柔、聪明、像真人”等形容词更有帮助。记忆是用户管理的背景资料，当前版本不会自动把每次对话总结并写入长期记忆。

## 默认 Lumi

默认角色设定为 20 岁、中文专业的大二女生，有课程、朋友、阅读与写作兴趣。气质偏孤高，熟悉后偶尔有一点腹黑；短回复是常见节奏。

人物提示把日常反应写成具体行为：可以有不想聊的时候、被冒犯后的不开心、道歉后仍然保留一点情绪。减少固定追问、对用户动机的分析和道歉评分。角色可以在文字里表达不愿继续聊，当前版本每次发送仍会请求模型回复，不包含真实自主意识或后台自主生活系统。

完整默认提示见 [COMPANION_DEFAULT_PROMPT_V8.txt](COMPANION_DEFAULT_PROMPT_V8.txt)，来源与设计取舍见 [提示词研究](COMPANION_PROMPT_RESEARCH.md)。默认字段的迁移采用旧默认内容的精确匹配；已有自定义人物、记忆和参考脸保留。

## 角色照片

1. 进入角色设置中的“TA 的长相”。
2. 上传、裁剪或替换参考照片，也可以只填写外貌描述。
3. 在陪伴聊天里请求一张照片，例如“拍张你在窗边喝水的照片”。
4. 后续生成继续使用参考脸，尽量保持人物一致。

参考脸不是一致性保证；图片服务的编辑能力与结果会影响外观。照片失败时可以修改本次描述再试；旧失败描述不会自动污染后续场景。明确询问图片真实性时，角色会如实说明图片由 AI 生成。

## 管理员的三套服务

进入管理控制台：

| 配置 | 负责什么 |
| --- | --- |
| 普通聊天模型服务 | 普通对话、助手与资料问答 |
| AI 陪伴专用服务 → 陪伴聊天 | 陪伴文字、上下文与兼容的工具调用 |
| AI 陪伴专用服务 → 陪伴照片 | 角色图片的生成与参考脸编辑 |

三套服务可使用不同的 API 地址、密钥与模型。文字接口支持 Chat Completions 和 Responses，选择与上游实际支持相符的模式；图片服务需要兼容的图片生成/编辑接口。

配置步骤：

1. 填写 API 基础地址和新的 Key。基础地址通常包含 /v1，以服务商说明为准，不要把 /chat/completions 填成基础地址。
2. 选择接口模式与鉴权方式。
3. 点击“获取可用模型并选择”。
4. 选择模型，点击“保存配置”使其生效。

获取模型与保存是两个步骤。只有在点击保存后，新的陪伴服务配置才生效。如果服务不提供模型目录，可手动填写服务商明确支持的模型名称。

地址和 Key 输入时遮挡，保存后只显示“已配置”。留空可以保留原配置；更换地址时必须同时填写新密钥，防止隐藏的旧 Key 被发送到新地址。离开页面或进入后台会清空未保存的凭据草稿。

## 连接问题怎么检查

| 提示或现象 | 检查方向 |
| --- | --- |
| 模型列表接口不存在或不受支持 | 核对基础地址的版本路径和上游是否提供 /models；该提示来自模型列表请求，不能直接推断文字聊天不受支持 |
| 鉴权失败 | 检查 Key、bearer / api-key 模式和账号额度 |
| 无法连接或超时 | 检查网关到服务商的网络连通性 |
| 模型请求未能完成 | 检查模型名称、接口模式、服务商支持的请求格式和额度 |
| 文字正常，照片失败 | 单独检查陪伴图片服务的模型、生成/编辑接口及参考图支持 |

输入正确地址后，先获取目录再保存，最后发送一条短消息验证实际聊天。目录成功不等于所有生成能力都已通过验证。
