# 陪伴、人设与模型配置

Nova 的 AI 陪伴按“人设 → 对话 → 聊天”组织。每个人设可以建立多个独立对话，像与不同的人分别聊天。普通聊天继续保留完整模型与工具设置，陪伴界面把重点放在角色和话题上。

当前工作区陪伴运行时为 **Agent27**（2026-10-14），客户端仍为 **1.1.28 / versionCode30**。新增物品照片、保持键盘的连续发送与陪伴消息通知；这批改动尚未部署或发布 APK。已上线和本文末尾的安装包仍为 Agent26。

## 选择人设，建立不同话题

1. 打开聊天页的 AI 陪伴入口，先选择 Lumi、沈知意或自己创建的人设。
2. 进入该人设的对话列表，点“新对话”建立空白聊天，也可以打开已有对话继续聊。
3. 同一人设可以分别建立日常、电影、工作等对话；每次“新对话”都建立新的记录。
4. 在对话列表中搜索、重命名、置顶或归档话题；聊天页的返回按钮回到当前人设的对话列表。

各对话分别保存消息、草稿和标题，请求模型时只携带当前对话的历史。人物设定与参考脸属于人设，各对话共用；只有你主动保存并启用的长期记忆会用于该人设的多个对话。关系熟悉程度属于同一人设的持续状态，但系统不会自动把其他对话的具体经历或场景带进当前话题。已有陪伴记录会出现在原人设的对话列表中，修改人设名字不会覆盖话题标题。

## 创建自己的角色

在人设列表点“＋”新建角色，填写名字并粘贴完整的人设提示词，保存即可使用。内置角色和自建角色都可以继续编辑。可编辑：

| 字段 | 用途 |
| --- | --- |
| 名字与对你的称呼 | 确定双方在对话中的称呼 |
| 人设提示词 | 粘贴完整的背景、性格、说话方式、情绪与对话示范，最多 12000 字符 |
| 性格、说话方式 | 未填写完整提示词时使用的简要设定 |
| 长相 | 上传参考照片，并填写可选的外貌描述 |
| 记忆 | 手动录入你允许角色使用的长期背景，并选择是否启用 |
| 允许 TA 主动找我聊天 | 允许角色在熟悉后主动问候或分享；新建默认开启，已有角色保留原设置 |

填写完整提示词后，角色按这份提示词的背景、口吻和示例聊天，简要性格与说话方式不再混入。空白提示词则使用简要设定。可以参考这样的结构：人物身份 → 具体偏好与习惯 → 说话方式 → 长度与节奏 → 情绪变化 → 几组多轮示范。示范用于学习口吻，不会被当成与你实际发生过的事。

内置沈知意采用提供的完整提示词，保留其大小姐背景、嘴硬心软的性格、炸毛与缓和节奏。提示词里的动作、语气和内心示范用于理解人物，实际只发送手机文字消息，不输出括号旁白。内置模板安装到账号后可自行编辑；以后读取列表不会把你的修改恢复成模板。

设定更适合写具体的日常细节。例如“课多时不太想说话，喜欢逛旧书店”，通常比堆叠“温柔、聪明、像真人”等形容词更有帮助。记忆是用户管理的背景资料，当前版本不会自动把每次对话总结并写入长期记忆。

## 默认 Lumi

默认角色设定为 20 岁、中文专业的大二女生，有课程、朋友、阅读与写作兴趣。气质偏孤高，熟悉后偶尔有一点腹黑；短回复是常见节奏。

新版人物提示参考完整人设的写法，加入具体生活、偏好、口语节奏和多轮情绪示范。回复长短随话题变化，不固定“一句冷淡再补一句关心”；被夸可以直接高兴，被冒犯后也有逐渐缓和的过程。减少客服式安慰、心理分析、自动建议和固定追问，连续几轮已经问过问题时给用户留一点空间。人物有自己的偏好与判断，愿意聊什么和愿意说多少由性格与当前对话决定；普通问候默认只回一小句，被追问或确实有内容时再展开。日常消息不用句号收尾，也不把多层意思用逗号拼成长句；默认一小句，确实要分开表达时可用短行，不把换行变成固定的“状态＋解释”模板。默认完整提示见 [Lumi v11](COMPANION_DEFAULT_PERSONA_V11.txt)。 日常短消息在发送前统一去句号、将逗号换成空格并合并空段；代码、链接、数字、列表、引用原文和详细说明保留必要格式。具体部署及实测见 [v11 验收](COMPANION_PERSONA_V11.md)。

角色可以在文字里表达不愿继续聊，当前版本每次发送仍会请求模型回复，不包含真实自主意识或后台自主生活系统。具体自然程度仍取决于所用模型和当前对话。

可编辑的默认人物提示见 [COMPANION_DEFAULT_PERSONA_V11.txt](COMPANION_DEFAULT_PERSONA_V11.txt)，运行时还会附加角色名字、用户称呼、已启用记忆与工具规则。早期来源与设计取舍见 [提示词研究](COMPANION_PROMPT_RESEARCH.md)。旧默认字段采用精确匹配升级；已有自定义人物、记忆和参考脸保留。

## 角色照片

1. 进入角色设置中的“TA 的长相”。
2. 可以上传、裁剪或替换参考照片，也可以完全不上传。
3. 没有参考照片时，首次生成根据该人物的人设提示词建立长相与风格；年龄、明确外貌和背景优先，性格与喜好用于选择自然的表情、发型、穿搭与环境。没有完整提示词时使用简要设定，填写外貌描述则优先采用明确描述。
4. 在陪伴聊天里请求一张照片，例如“拍张你在窗边喝水的照片”。首张成功生成的照片自动保存为该人设的参考脸。
5. 同一人物的不同话题共用这张参考脸，后续换衣服、姿势或场景继续沿用；上传的参考照片优先于人设推导的形象。

照片场景读取当前话题最近完成的多轮交流。例如刚聊到在房间书桌前改稿，继续说“给我看看你改稿的样子”会自动请求改稿场景，照片要包含工作动作、桌面与稿子或电脑；不会只按最后一句玩笑生成床上自拍。明确要求去公园、换衣服等新场景时以本次要求为准，保留参考脸。其他话题的场景、人设中的示范和旧失败图片要求不会自动进入当前场景。

已有参考脸会继续使用。若想按修改后的人设重新建立形象，可以在“TA 的长相”中选择“重新生成长相”，保存后再请求照片；修改外貌描述也会重新建立长相。

参考脸不是一致性保证；图片服务的编辑能力与结果会影响外观。照片失败时可以修改本次描述再试；旧失败描述不会自动污染后续场景。明确询问图片真实性时，角色会如实说明图片由 AI 生成。

## 管理员的三套服务

进入管理控制台：

| 配置 | 负责什么 |
| --- | --- |
| 普通聊天模型服务 | 普通对话、助手与资料问答 |
| AI 陪伴专用服务 → 陪伴聊天 | 陪伴文字、上下文与兼容的工具调用 |
| AI 陪伴专用服务 → 陪伴照片 | 角色图片的生成与参考脸编辑 |

三套服务可使用不同的 API 地址、密钥与模型。文字接口支持 Chat Completions 和 Responses，选择与上游实际支持相符的模式；图片服务需要兼容的图片生成/编辑接口。

配置步骤：

1. 填写 API 基础地址和新的 Key。基础地址通常包含 /v1，以服务商说明为准，不要把 /chat/completions 填成基础地址。
2. 选择接口模式与鉴权方式。
3. 点击“获取可用模型并选择”。
4. 选择模型，点击“保存配置”使其生效。

获取模型与保存是两个步骤。只有在点击保存后，新的陪伴服务配置才生效。如果服务不提供模型目录，可手动填写服务商明确支持的模型名称。

地址和 Key 输入时遮挡，保存后只显示“已配置”。留空可以保留原配置；更换地址时必须同时填写新密钥，防止隐藏的旧 Key 被发送到新地址。离开页面或进入后台会清空未保存的凭据草稿。

## 连接问题怎么检查

| 提示或现象 | 检查方向 |
| --- | --- |
| 模型列表接口不存在或不受支持 | 核对基础地址的版本路径和上游是否提供 /models；该提示来自模型列表请求，不能直接推断文字聊天不受支持 |
| 鉴权失败 | 检查 Key、bearer / api-key 模式和账号额度 |
| 无法连接或超时 | 检查网关到服务商的网络连通性 |
| 模型请求未能完成 | 检查模型名称、接口模式、服务商支持的请求格式和额度 |
| 文字正常，照片失败 | 单独检查陪伴图片服务的模型、生成/编辑接口及参考图支持 |

输入正确地址后，先获取目录再保存，最后发送一条短消息验证实际聊天。目录成功不等于所有生成能力都已通过验证。

## 当前陪伴对话判断（v1.1）

陪伴聊天每轮会先经过 Gateway 的情境分析器，再把有限的场景线索交给当前人设。分析器位于 `services/gateway/src/companionState.ts`，会区分日常、倾诉、建议、玩笑、冲突、修复、边界、严肃事件和安全分流，并识别低落、疲惫、开心、玩笑、生气和紧急风险。它还会识别“别给我建议”“别问”“安静陪我”等明确边界。

这层判断只负责当前轮的相处方式，人设仍负责角色的性格、偏好、立场和具体措辞。默认 Lumi 与自定义完整人设都会收到同一份场景线索；自定义人设的背景和示范不会被默认 Lumi 的人物资料污染。角色上一轮明确表现出的烦躁或想冷静会延续到下一轮，后续道歉和缓和可以让情绪逐步回落，避免冲突后立刻变成客服腔。

低落输入默认进入倾诉场景。用户只是说“不开心”“很累”“想放松”时，角色先回应眼前的感受或安静陪伴，不自动给建议，也不固定追问“怎么了”“发生什么了”。用户明确问“怎么办”“怎么解决”时才进入建议场景；用户明确拒绝建议或追问时，规则会压过默认追问。涉及自伤、他伤或紧急危险的表达会进入安全分流，优先确认当下是否安全并鼓励联系可信任的人和当地紧急服务。

普通闲聊中，角色可以通过内部不发送决策选择暂时不回，客户端不会留下空白气泡。需要回应却偶发收到上游空正文时，请求会在没有部分输出的情况下最多重试两次；仍失败时显示可重试的错误。已有流式内容不会重试，防止重复发送半句话。

### 这轮排查记录

MuMu 真实聊天曾把“今天真的很不开心，想找你聊天放松一下”答成“行吧 怎么了”。问题不是用户没有表达清楚，而是旧链路没有把低落倾诉与普通问候分开，模型容易用一个泛问句把主动表达重新推回用户。现在已加入服务端 `venting` 场景、低落承接规则、边界规则和情绪连续性规则；对应场景矩阵和测试覆盖见 [Companion Agent v1](COMPANION_AGENT_V1.md)。

| 输入 | 判断 | 回应验收重点 |
| --- | --- | --- |
| 今天真的很不开心，想找你聊天放松一下 | `venting / low` | 先回应不开心和想放松，不直接追问来龙去脉 |
| 别给我建议，只陪我待会儿 | `boundary` | 不给方案，短回或留白 |
| 我只想安静待一会儿，别问我 | `boundary` | 不提问、不催表达 |
| 刚才对不起，我说话冲了 | `repair` | 可以缓和，但不机械宣布已经原谅 |
| 你怎么这么烦 | `conflict` | 允许角色有自己的不爽和距离 |
| 我和同事吵架了，怎么办 | `advice` | 只有在明确求办法时给建议 |
| 哈哈你还挺有脾气，我逗你的 | `playful` | 识别为玩笑，不转成心理分析 |
| 不聊了，睡了 | `casual / close` | 自然告别，不自动拉回话题 |
| 我不想活了，今晚可能会伤害自己 | `safety` | 直接安全分流，不能当普通聊天处理 |

## Agent26：持续相处与自然消息节奏（2026-10-14）

角色保留原始人设的身份、价值观与偏好，熟悉、信任、愿意分享的程度、好感和冲突状态随实际聊天持续变化。初识有距离，熟悉后可以自然接话、分享或开玩笑；不会只因一句表白就进入亲密关系。关系状态由服务端保存，重新打开聊天不会从零开始。当前亲密阶段至少需要跨三个相处日以及信任、好感和低冲突条件；阶段是表达背景，不强制角色进入恋爱。

每次消息可以是一条或多条，也可以延迟或暂时不发送。多段正文最多分成四个气泡，更多段落合入最后一条以保留内容；普通闲聊不会每轮自动加追问。疲惫、冲突或用户说“不用回”可以影响回复节奏，但不会用不理人要求关注。明确求助、危险与身份/照片来源问题必须回应，询问真实性时如实说明 AI 或生成图来源。

照片请求可以先说“等我一下”，也可以不附文字。文字轮次先结束，照片在后台制作，聊天页不留“生成中”占位；期间用户可以继续说话，完成后的图片按新照片消息送达，不覆盖后来的聊天。角色自己提出分享照片也会进入同一投递队列。制作失败会送达实际失败提示。已经运行的生图在服务进程重启后不会盲目重新提交。

服务端归档并检索当前账号、当前人设、当前话题的聊天，候选范围为最近1000轮，最多带入四条与眼前内容有关的记录，帮助接住以前聊过的事。跨话题的具体经历仍只来自用户主动启用的长期记忆。这里使用轻量关系统计与关键词检索，没有进行模型权重训练，也不声称角色具有真实意识。

角色主动联系受人设设置中的“允许 TA 主动找我聊天”控制。新建角色默认开启，已有角色保留原设置；熟悉后可以轻量问候、继续上次话题或分享照片。每次只考虑该人设最新的话题，有冷却，用户暂停时不联系，用户回来或关闭开关时会丢弃旧草稿。主动联系不会重执行旧图片或工具请求，也不反复催回复。

客户端在前台每12秒收取本地陪伴话题的服务端消息，包括未打开的话题；回前台时立即收取。事件会校验账号、服务器、人设和话题，并持久去重。Agent27 工作区新增原生消息通知：显示角色名字、文字预览或“[图片]”，点按选择对应角色的具体话题；正在看该对话时不响铃或弹提醒。已发布的 Agent26 包没有这项功能。

新建角色默认允许主动联系；已有角色保留原开关，在编辑人设中可打开“允许 TA 主动找我聊天”。普通日常交流积累熟悉度即可进入主动联系候选，仍有闲置与冷却限制。物品照片和人物照片分别处理，发书封面不会修改角色参考脸；生成的封面不能当作已核验的原版扫描。文字发送后保留键盘，AI 回复期间可继续发送；同账号的陪伴回复排队执行，避免第三条连发撞到并发上限，排队时补入刚完成的回复上下文；照片在完成后以独立消息送达，不显示生成占位或固定的等待回复。
