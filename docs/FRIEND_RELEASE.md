## 修复范围

- 普通注册只需要邮箱、密码和客户端自动生成的设备标识；昵称默认“新用户”，之后可在个人资料修改。
- 注册成功直接取得 Session 和管理员发布的默认模型，不要求用户填写 API Key、服务器或模型参数。
- 530、502 等代理错误有明确的服务离线提示；登录页面提供重新连接入口。
- App 启动遇到临时网络/网关错误时保留 Session，仅在明确 401/403 时清除登录凭证；模型目录暂时不可用不再导致退出登录。
- API 和 REST 生成拒绝代理返回的 HTML 成功页，避免将错误页面当作空白回复。
- `GET /v1/setup/status` 返回 `providerConfigured`（仅检查配置，不保证上游实时可用，不含 Key）。
- 分享包构建前后都检查公网健康、管理员初始化、注册开关、模型配置；默认拒绝将临时地址作为固定服务分发。

## 本机临时恢复（管理员操作）

```powershell
.\scripts\start_gateway_supervisor.ps1
.\scripts\stop_gateway_supervisor.ps1
```

守护进程会在本机网关进程异常退出后重启它，使用既有 `.env` 和数据库。不安装系统服务、不修改开机启动项、不重置账户或密钥。日志位于 `.run/gateway-supervisor.*.log`。本机重启后需要重新启动守护进程。不要同时启动多个网关；使用守护模式时也应使用对应的停止脚本。

**这无法让关机的电脑继续提供服务，也无法保证临时 Tunnel 域名永久可用。不要自动重建临时 Tunnel 后继续分发旧 APK，重建的域名通常不同。**

3. 完成管理员和模型配置，开启普通注册；用全新账号做公网注册、文字、附件和 WSS 端到端验证。

5. 将 APK 上传到受控的 Release/对象存储，发布 SHA-256；下载可用不等于聊天网关一直在线。

## 认证与真实聊天门禁（2026-09-10）

`npm run gateway:check-chat -- <明确指定的HTTPS网关根地址>` 使用受控环境提供的 `NOVA_RELEASE_SESSION_TOKEN`，不接受命令行令牌。临时域名需额外显式 `--allow-temporary`；这不会把临时入口变成常驻服务。正常分享构建脚本已强制调用，不需另传重复开关。

验收顺序：健康/初始化配置 → 无认证必须明确401 unauthorized → 当前会话及可用默认模型 → WSS认证ready → 一次关闭全部工具的合成请求 → 非空delta+done → 同requestId、conversationId、正文的completed快照。HTTP/WSS禁止重定向，JSON限制256KiB、WS帧64KiB、回复32KiB，超时/错误不自动重试；失败仅尝试取消本次合成任务，取消请求成功不保证上游零费用。报告不包含会话令牌、账户标识、模型回复或远端任意错误正文。

本机诊断可显式使用 `--local-only`，只接受HTTP 127.0.0.1根地址，报告永远是loopback-only/publicChatVerified:false；**正常发布脚本不使用也不接受此选项替代公网验收**。健康检查和验收报告不是签名证明，不涵盖新账号注册、附件、不同运营商网络、真机交互或长期在线，正式发布仍需前述人工/设备验收。
