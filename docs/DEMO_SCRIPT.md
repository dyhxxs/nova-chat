# Nova Chat 演示脚本

目标时长约 3 到 5 分钟。演示只围绕一条主线展开，扩展功能放在最后一句带过。

## 演示前准备

- 启动 Gateway，并确认 `/healthz` 与 `/readyz` 返回正常；
- 准备一个管理员账号和一个普通用户账号；
- 在管理员控制台保存一个可用的 OpenAI-compatible Provider；
- 准备两份仅用于演示的合成资料，例如部署手册和安全基线；
- 打开指标时使用只在本地终端保存的 `METRICS_TOKEN`，不要把 Token 放进录屏。

## 0:00–0:30 说明问题

可以这样介绍：

> Nova Chat 是一个可自托管的多模型 AI 助手平台。移动端负责交互，Gateway 负责账户、权限、模型路由和个人资料库；模型 Key 只留在 Gateway，用户不需要把第三方 Key 写进手机。

展示项目结构：`apps/mobile`、`services/gateway`、`packages/protocol`。

## 0:30–1:00 管理员配置和权限

1. 打开初始化页面，说明管理员初始化 Token 只用于首次创建管理员；
2. 进入管理员控制台，展示 API Base URL、协议、鉴权方式、默认模型和允许模型列表；
3. 说明保存后界面只显示 Key 已配置或末四位，不把完整 Key 返回给普通用户；
4. 切换普通用户，展示用户只能看到允许使用的模型，不能访问管理接口。

## 1:00–1:45 上传资料和隔离

1. 普通用户上传一份合成资料，或在资料库中录入正文；
2. 展示资料列表、字符额度和来源名称；
3. 用第二个用户访问第一用户的资料 ID，展示 `404` 或权限拒绝；
4. 回到第一个用户，提问一个资料中有明确答案的问题。

可以强调：资料按 `user_id` 查询，附件下载也会再次检查所有者；资料内容进入模型前被标记为不可信数据。

## 1:45–2:30 带来源的流式回答

1. 打开“资料问答”选项，提问“生产环境的主密钥需要满足什么条件？”；
2. 展示 WebSocket 的增量回答和 `[资料1]` 来源；
3. 追问一个资料没有覆盖的问题，展示 Gateway 本地拒答且不会调用模型；
4. 点击停止，说明取消会释放任务状态，随后重新发送同一会话不会把取消正文带进下一轮上下文。

如果要展示 REST fallback，可以在浏览器开发工具或脚本中禁用 WebSocket 握手，说明尚未开始生成时可以退回 REST；已经开始生成后不自动重试，以减少重复计费风险。

## 2:30–3:15 运维和错误处理

在终端执行：

```bash
curl -i https://chat.example.com/healthz
curl -i https://chat.example.com/readyz
curl -i -H "X-Request-ID: demo-trace-001" https://chat.example.com/health
curl -i -H "Authorization: Bearer $METRICS_TOKEN" https://chat.example.com/metrics
```

说明：

- `/healthz` 只回答进程是否存活；
- `/readyz` 检查数据库，并报告 Provider 是否已配置；
- `X-Request-ID` 会原样回传并进入结构化日志；
- metrics 按方法、路由模板和状态码聚合，不把动态用户路径写进标签；
- 日志会脱敏认证头、Cookie、API Key、密码、消息正文和工具指令。

故意输入一个错误的模型或无效请求，展示脱敏错误响应和 `requestId`，再用这个 ID 定位服务器日志。

## 3:15–4:00 评测和限制

执行：

```bash
npm run knowledge:evaluate
```

打开 `artifacts/knowledge-evaluation/report.md`，说明评测集是合成数据，包含 40 条单文档、20 条跨文档、10 条应拒答和 10 条注入夹具。报告中的 Recall@5、来源精确率和拒答准确率只描述当前 SQLite FTS5 词法检索 baseline；注入夹具命中率不等于模型安全评测。

最后诚实说明：混合检索、向量检索、集中式监控、自动灾备和大规模压测尚未完成，线上指标不能用本地合成数据代替。

## 演示结束语

> 这个项目的重点不是堆很多模型功能，而是把模型调用放进一个可验证的产品链路：用户身份、权限、Key 保护、资料隔离、流式任务状态、错误关联和可重复评测都由 Gateway 统一管理。
