# 升级兼容约定

用户要求更新后旧版仍能使用、升级后原记录仍保留。下列要求作为今后发布约束，不通过安装提示让用户卸载或清除数据。

## 手机端

- 保持 com.novachat.mobile 包名和已发布签名。每次递增 versionCode，核对新包与前一公开包的签名证书；生产签名切换须另行设计迁移，不能直接换签名后要求卸载。
- 默认保持固定网关来源。账户数据按 userId + gateway 命名空间保存，网关变更是账户服务迁移，必须显式规划数据和会话迁移，不能当作普通 APK 更新。
- 当前账户快照为 v7，Android 存储使用现有 SQLite 驱动。不因 App 版本号变化删除表、重建空库或改变存储 key。
- 新增记录字段允许缺省；需要迁移时先保留原始快照/恢复副本，写入并读回验证后才切换。读写失败或未知未来格式不得覆盖原记录。
- 启动先恢复凭证并验证账号，再读取对应的私有历史。短暂离线/上游错误不应清空会话和数据。
- 发布回归必须覆盖普通/陪伴聊天、消息、照片引用、收藏、草稿、助手预设和设置，以及重复启动和原数据保留。现有 gatewayUpgrade、storePersistence、localStorage 等测试是发布门槛的一部分。

## 网关及旧客户端

- 持续兼容现有 /v1 REST/WSS 请求。新字段使用默认值或能力协商；严格 schema 的旧客户端不能收到未知字段。陪伴资料 v2 当前通过 x-nova-companion-profile-version 显式开启。
- 数据库迁移先增加表/列，不清空已有表。旧客户端 PATCH 未提供的新字段必须保留原值。
- 部署保留既有数据库、上传目录、SERVER_MASTER_KEY、普通模型设置、管理员及登录会话。图片文件本体和文件记录一起保护。
- 部署前备份一致 SQLite、上传文件及源码/运行镜像；备份限制访问且不发布。回滚优先切回旧运行镜像并保留新增数据；恢复数据库前必须处理备份之后的新增记录，不能直接覆盖线上数据。
- 同时验证最新/旧客户端协议，旧数据逐行一致、原会话和 provider 不变。旧版本下载按不可变路径保留，不把新 APK 字节覆盖进旧文件名。

## 更新提示

现在不检查最低版本，也不强制更新。后续更新提示和强制更新独立开发；提示更新默认允许继续使用。强制升级不能以清空历史作为代价，也不能随普通后端部署自动阻断旧客户端。

## 数据边界

覆盖安装保留同一手机的本地记录，服务器角色和文件继续使用。卸载、清除数据、换手机和跨服务器迁移需备份/同步方案；当前聊天历史并非跨设备云同步。
