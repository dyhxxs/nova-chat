# 可用性与账户安全扩展指南

适用范围：Nova Chat 1.1.27 源码。本文说明账户安全、本地数据与备份的使用方式；完整原生平台验收项目见 [人工验收清单](QA_CHECKLIST.md)。

## 1. 功能入口

| 想做什么 | 入口 | 说明 |
|---|---|---|
| 保存/迁移聊天文本 | 设置 → 数据与帮助 → 数据与备份 | 全量 JSON 导出、文件预览和增量导入 |
| 整理或分享一个对话 | 历史记录 → 对话菜单 | 改名、置顶、归档、单个 JSON/Markdown 导出 |
| 使用固定工作角色 | 聊天输入框上方「助手库」或设置 → 助手库 | 内置模板、自定义模板、复制、编辑、删除、开始对话 |
| 迁移自定义助手 | 助手库 → 备份或导入助手，或数据与备份 → 助手模板迁移 | 独立格式、私有指令预览、增量导入 |
| 登录保存或退出清理失败 | 全局提示条（退出后在登录页保留） | 重试最新登录的读/写/删除操作 |
| 保留未发送文字 | 正常输入后切换对话 | 自动保存各对话的文字草稿，不保存待上传附件 URI |
| 查看/退出登录设备 | 设置 → 账户安全 | 查看自己的有效会话，退出指定设备或其他设备 |
| 更换密码 | 设置 → 账户安全 | 验证旧密码，成功后所有设备重新登录 |
| 定位连接问题 | 设置 → 连接诊断 | 地址、健康接口、模型目录和实时握手，不生成模型内容 |
| 保存失败或本地数据损坏 | 提示条 → 数据与备份 | 重试本地保存，或导出原始恢复副本 |

## 2. 对话备份不是完整设备备份

### 导出

1. 打开「数据与备份」，点击「导出全部对话 JSON」。归档对话也包含在内。
2. 在系统分享面板选择可信的文件保存位置；Web 使用本地下载。
3. **确认目标位置真的出现了文件。**打开分享面板不等于保存成功，取消分享也不会形成外部备份。
4. 超过文件限制时，可在历史菜单逐个导出对话；单个超大对话仍受 JSON 文件限制。

包含：对话标题、时间、置顶/归档标记、消息正文、消息状态、模型名称、附件名称/MIME/大小/类型。

不包含：Session Token、API Key、账户资料、网关地址、系统指令、助手模板及固定指令、未发送草稿、附件二进制、本地 URI、服务端文件 ID、生成任务 ID、原始错误响应。

这里的“不包含”指**配置字段被排除**，并不会识别或擦除你自己写进消息正文中的密码、地址或其他敏感信息。文件仍是未加密明文，不能随意公开。

### 导入

1. 选择 Nova v1 JSON 文件。
2. 查看对话/消息数量并确认合并到当前账户。
3. 导入是增量合并，不清空或覆盖已有历史；按来源 ID 跳过重复对话。
4. 同一备份重新导入不会更新已存在的副本。因此，备份不是双向同步，也不是版本冲突合并工具。
5. 文件选择期间如果切换账户或网关，旧的待导入内容不会导入新账户。

完整文件先通过格式、版本、重复来源 ID 和大小检查，再改变状态。导入会生成新的本地对话/消息 UUID。原来正在生成的消息改为已取消，不启动、恢复或重放任何模型任务。附件转换为正文中的文件信息，原文件需单独保存、重新上传。

### 格式与限额

- 顶层标识：`{"format":"nova-chat-conversations","version":1,"exportedAt":...,"conversations":[...]}`。
- 最大 20 × 1024 × 1024 字节 UTF-8；中文和 emoji 按真实编码长度计数。
- 最多 5,000 个对话；每个对话最多 50,000 条消息；单条正文最多 2,000,000 个 JS 字符单元；单条消息最多 100 个附件元数据。
- 以 `apps/mobile/src/lib/conversationBackup.ts` 的 schema 为实际格式定义，不接受任意聊天应用导出的 JSON。

## 3. 历史整理与草稿

- 「最近」隐藏归档；「置顶」只显示未归档置顶项；「归档」和「全部」提供独立筛选。
- 置顶优先，再按更新时间排序。
- 搜索覆盖标题、消息正文、模型名、附件名称；执行 NFKC 规范化、忽略大小写；多个空格分隔关键词须全部出现，不是语义搜索。
- 草稿会显示在历史摘要中，但当前不在全文搜索范围内。
- 生成中的对话不能归档；向归档对话发消息时会重新激活它。
- 草稿每个对话最多 10,000 个字符单元。发送成功接入请求流程后，只清空与已发送文本完全相同的草稿，避免误清掉用户刚写的新文字。
- 附件选择属于临时状态；未发送附件 URI 不持久化，重新进入需重新选择附件。
- 后台切换、退出和换账户时会刷新待写入历史，但突然掉电、强制杀进程或磁盘故障仍可能使尚未落盘数据丢失。

## 4. 助手库

内置「写作搭档」「代码审阅」「学习教练」「任务规划」。可以直接使用、查看指令或复制为自定义模板。自定义模板支持名称、简介、系统指令和开场草稿。

- 每个账户/网关最多 100 个自定义助手。
- 名称 1–60、简介最多 200、系统指令 1–20,000、开场草稿最多 10,000 个字符单元。
- 开始对话只创建本地会话、填入草稿，**不会自动发送或计费**。
- 对话创建时冻结助手名称与指令。以后编辑或删除模板，不会悄悄改变已有对话。
- 助手对话使用自己的固定指令；普通对话继续使用全局设置中的指令。
- 自定义模板与对话一样绑定本机账户和网关，不跨账户继承。
- 对话备份仍刻意不导出助手配置和草稿。助手现在有独立备份入口；对话未发送草稿仍需另行妥善保存。

助手只是可复用的提示配置，不是独立代理、代码执行器、联网搜索器或新增模型。是否支持工具、是否遵循指令、内容准确性与费用仍取决于选用模型及服务商。

### 助手模板备份与导入

1. 进入「数据与备份 → 助手模板迁移」，可导出当前账号全部自定义模板。文件名以 nova-assistants- 开头。
2. 此文件**包含完整私有系统指令和开场草稿**，但不包含聊天、凭据、账户/网关配置。字段白名单不会擦除自行写入指令中的秘密；仍应把文件当敏感明文。
3. 选择文件后预览模板名称、用途、指令前 800 字和开场草稿前 300 字，超长内容明确标记截断。确认来源可信后勾选确认，再增量导入。完整内容导入后可在助手库查看和修改，使用前请检查。
4. 按来源标识或完全相同的名称/描述/指令/开场草稿去重。相同来源的新版本不会覆盖本地编辑；相同名称但不同内容允许同时保留。编辑已导入模板会保留来源标识。
5. 文件整体校验成功后才应用；导入后超过 100 个自定义模板则整体拒绝，不做部分导入。确认时重新计算容量并校验账号、网关和登录会话未改变。
6. 独立标识：`{"format":"nova-chat-assistants","version":1,"exportedAt":...,"presets":[...]}`，最大 10 MiB UTF-8。不接受对话备份或任意第三方格式。
7. 导入只创建本地模板，不创建聊天、发送消息、恢复任务或调用模型。开场草稿不是自动执行指令。

## 5. 账户安全与实时撤销

会话列表只展示当前账户的有效会话元数据：会话 ID、客户端自报设备 ID、创建时间、到期时间、是否当前会话。不返回原始令牌或令牌哈希，不提供 IP/地理位置、可信硬件指纹或真实在线状态。

- 「退出其他设备」保留当前会话，撤销其他有效登录。
- 指定会话撤销仅能操作自己的会话；管理员身份也不能借此接口枚举或撤销其他用户的会话。
- 修改密码需要旧密码，新旧密码要求 8–200 个字符，NFKC 等价的新旧密码会被拒绝。
- 每账户 15 分钟最多 5 次符合基本格式的改密尝试；超限返回 429 和 Retry-After。
- 改密成功在 SQLite 事务中更新哈希并撤销**包括当前设备在内的全部会话**。这不是忘记密码/邮件找回功能。
- WebSocket 不再只在 hello 时认证：每帧和心跳检查会话、禁用状态和角色。退出、会话撤销、改密、管理员更新会触发失效检查；过期会话另由 15 秒清扫覆盖。
- 无效认证连接以 4401 关闭，并取消该失效会话关联的运行任务。权限降级会刷新在线身份，不能继续使用原管理员权限。
- 单纯网络断开/应用切后台不等于撤销登录，不应取消仍有效的 durable 生成任务。
- 已经发给上游的内容、已经产生的费用无法因撤销而追回。直连模式不受网关会话撤销保护。

### API 摘要

均要求正常账户 Bearer Session，旧 APP_ACCESS_TOKEN 身份不能使用。

| 方法 | 路径 | 成功返回 |
|---|---|---|
| GET | /v1/auth/sessions | { sessions: [{ id, deviceId, createdAt, expiresAt, current }] } |
| DELETE | /v1/auth/sessions/:sessionId | { ok: true }；不存在或非本人返回 404 |
| POST | /v1/auth/sessions/revoke-others | { ok: true, revoked: number } |
| POST | /v1/auth/password | body 为 { currentPassword, newPassword }，成功 { ok: true } |

移动端会校验成功响应结构，HTTP 200 本身不等于操作成功。旧网关返回 404 时，账户安全页提示升级，而不是误报已修改密码。建议先在测试环境升级网关再验收新客户端。

## 6. 无付费连接诊断

顺序为地址检查 → 无令牌 GET /health → 带认证 GET /v1/models → WebSocket /v1/chat/stream 的 hello/ready → 主动关闭。

- 健康接口必须返回 Nova 网关标识和成功字段，错误服务/HTML 代理页不通过时，不继续发送认证令牌。
- 不调用生成接口，不发送 start，不上传文件，不请求上游模型。
- 默认每项 6 秒超时，支持取消，关闭并清理 WebSocket 与定时器。
- 未登录时只检查公共健康接口；不接受地址内用户名、密码、查询参数和片段。
- HTTP 显示不加密警告，只应在可信本地环境临时测试。
- 可复制的报告只包含检查时间、客户端版本/平台、HTTP(S) 类型、耗时及本地生成的结果摘要。
- 报告不包含服务器域名、令牌、用户/设备 ID、模型名称、聊天或原始服务端错误体；不要把它与用户自行编辑的其他信息混淆。

诊断全绿只代表本次网关基础链路可用，**不代表上游 Key、余额、权限、模型生成、附件解析、图片或工具能力可用**。

## 7. 本地保存与损坏恢复

历史、设置、助手、草稿按「用户 ID + 已认证网关地址」隔离。全局 bootstrap 只保留重新连接必需的网关地址/设备 ID，不保存私有系统指令。已认证地址与可编辑设置分离，避免历史误写给其他网关或凭据随设置变化发送到另一主机。

正常快照恢复会验证每条对话、消息和助手，过滤损坏记录及重复 ID。发生修复前，先保存**原始未修改字符串**为账户/网关范围内的恢复副本，再写入修复结果。

### 看到红色保存/恢复提示时

1. 不要卸载应用或清除系统应用数据。
2. 如果当前还有新写的消息，先导出标准会话备份；助手可另导出模板备份；未发送的对话草稿仍需另行保存。
3. 短暂保存失败可点「重试本地保存」。若提示读取被阻止，先保留新内容，再退出重登重试读取；当前没有自动合并未保存新数据的机制。
4. 在「数据与备份」导出恢复副本，自己妥善保管。不要不经脱敏就发送给维护者。

原始恢复副本**不是**可直接导入的 Nova 标准备份，可能包含服务器地址、系统指令、助手、草稿、聊天和旧文件引用。已存在不同恢复副本时不会覆盖它；原快照读取失败、版本未知、归属不匹配或保护副本失败时，会阻止空白状态覆盖旧数据。

导出恢复副本也检查当前账户/网关/会话是否变化；JSON 可解析且声明了其他用户归属时拒绝导出。损坏到不可解析的数据只能依据账户存储范围进行保护，不能保证恢复出全部原文。

### 原生 SQLite 迁移

Android/iOS 的账户快照和恢复副本现在使用 expo-sqlite；Web 继续使用 AsyncStorage。全局连接配置和非秘密登录 intent 标记仍在 AsyncStorage，令牌只在 SecureStore。

旧版账号首次读取时，先将原始字符串和活动快照保存在同一 SQLite 事务中，验证后再把旧 AsyncStorage 值替换为小型迁移标记。SQLite 成为权威来源；读取失败不会退回过期副本，迁移标记存在但数据库缺记录时阻止空白覆盖。原始迁移档案不被后续编辑或正常清空对话覆盖，可从「导出迁移前原始快照」导出。

迁移档案与恢复副本都可能包含私有配置，**不是通用可导入备份**。清空对话只清空列表，不删除助手、恢复/迁移档案及已导出的文件，也不承诺安全擦除磁盘。

**不要直接降级旧客户端。**新存储和版本化凭据不是旧版可以正确读取的格式。升级/回滚步骤、故障边界见 [存储迁移与回滚指南](STORAGE_MIGRATION.md)。

### 存储维护、分享与大历史

「数据与备份」新增「存储检查与保留档案」：显示当前账号/网关四类已保存正文的大小；统计不包含附件本体或外部备份，也不是整库磁盘占用。

原生端可先预览，再勾选已核实外部备份，手动确认清理恢复/迁移档案。预览与确认前各保存一次当前内容；故障恢复区可分别导出三类保留原文。标准聊天 JSON 不含助手和草稿，不能只导出聊天就认为所有原文已有副本。读取受阻、保存失败、账号变化或档案版本变化时拒绝清理；不会自动清理、清空当前历史或触碰其他账户。清理只是逻辑删除，不保证立即释放磁盘空间，也不是安全擦除。Web 只展示统计，不提供不具备跨标签页原子性的清理。详细流程见 [存储指南](STORAGE_MIGRATION.md#6-保留档案维护第三轮)。

导入聊天/助手后，如果内存合并成功但本地保存失败，提示会明确区分这两个阶段：不要关闭应用；重试本地保存，必要时先导出当前内存内容。不要把此状态误认为根本没有导入而反复操作。

所有分享入口在打开系统分享/下载之前再次检查账号和页面有效性；过期异步结果不覆盖新账号提示。原生临时写入失败时立即清理自身文件，已开始分享则保留约一小时供接收方读取；Web 成功请求下载后保留 URL 约一分钟。系统已经打开的分享、接收应用保存的副本无法撤回；分享入口返回不证明外部文件已保存。

历史搜索使用当前账户内有限额的规范化正文缓存，并延后计算输入筛选。标题、正文、模型与附件名仍支持多词匹配；不索引草稿和助手私有指令。缓存正文限 2,000,000 个 UTF-16 字符（不含对象额外开销），超预算内容仍能搜索，但不会全部保存在缓存中。替换/删除的对话对象被清出缓存，账号变化创建新选择器。列表预览最多 280 字符；完整正文不被截断。性能基准只能说明本机合成场景，不代表所有手机均流畅。

### 凭据错误与退出保护

- SecureStore 读失败时暂停自动登录，显示「重试读取登录」；不把失败静默视为正常退出。
- 新登录先写非秘密 blocked intent，再验证加密区中保存的凭据 envelope，最后激活对应随机 nonce。envelope 同时绑定认证时网关，避免重启时使用过期 bootstrap 地址发送令牌。
- 保存失败时当前内存登录仍可使用，但会显示重试提示；重启可能需要重新登录。如果最初的 intent 都写失败，旧登录可能仍残留，因此不可忽略警告。
- 退出时分别尝试写 blocked intent 和删除 SecureStore 凭据；任一保护成功即可阻止本次旧登录自动恢复。未全部完成时，警告在登录页仍显示，可重试清理。
- 两个存储都失败时无法保证持久退出，界面会明确提示重启可能恢复旧登录。完成清理前不要把设备交给他人；必要时从另一可信设备撤销这次服务器会话。
- 重试只作用于最新会话；慢登录和退出串行处理，过期异步结果不会更改新会话的提示或恢复旧账户。
- Web 没有使用不安全的 localStorage 代替 SecureStore 保存令牌。浏览器若不支持此安全存储，会显示读/写失败提示，登录只应视为当前内存会话。

## 8. 明确边界与发布前验收

- 原生快照已迁至 SQLite，避免继续依赖 AsyncStorage 大单行/总额存储；仍然是整体 JSON 快照，不是逐消息数据库、加密数据库或无限容量存储，仍受内存与磁盘容量影响。旧行若已经大到无法由 AsyncStorage 读取，本轮无法保证自动恢复。
- 没有新增云同步、加密备份、附件打包迁移、邮件找回、MFA、后台自动备份或共享助手市场。
