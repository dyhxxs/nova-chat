# 微信式语音聊天模块 · 2026-10-14

本轮已完成移动端和网关实现，并通过本地真实中转联调。预览客户端仍使用 1.1.28 / Android versionCode 30，包名 com.novachat.mobile。公网网关尚未部署本轮语音接口；本轮 APK 连接公网后，要先升级网关才能使用新增语音功能。

## 使用方式

1. 在聊天输入框左侧点击麦克风，按住说话，松开发送；上滑约 70px 后松开可取消。
2. 点击录音区域下方的切换文字，选择“语音转文字”。松开后把识别结果填入输入框，可以编辑再发送。
3. 点击语音消息气泡播放或暂停，点击“转文字”展开识别结果。播放另一条语音会停止前一条。
4. 点击输入框右侧加号，打开语音设置。每个会话分别保存回复方式和音色。

AI 回复方式：

- 自动：你发送语音时，AI 也生成语音；你发送文字时，AI 使用文字。
- 语音：AI 的文字回复同步生成语音气泡，主动/延迟回复同样遵守这个偏好。
- 文字：AI 保持文字回复。

后续已接入用户提供的少女音克隆：配置 VOICE_FEMALE_CLONE_ID 后，默认女声和旧女性选择统一使用该专属音色，另可选择小天、刘飞男声。配置与试听见 [VOICE_CLONE_2026-10-14.md](VOICE_CLONE_2026-10-14.md)。未配置克隆时仍使用原有 Vivi、小何、邻家女孩。文字仍保留在消息中；合成失败时可读文字并点按重试。语音不会自动播放，点击后播放，避免收到多条消息时互相打断。

## 录音与恢复

单条录音最长 60 秒，上传限 8 MB。低于 600ms 的录音不发送。应用切到后台或离开会话时停止并取消正在录制的音频；失败的发送保留录音，切换键盘再回来可以继续重试。切换会话会清理未发送录音，已经上传的消息音频保存于网关并要求登录鉴权下载。

AI 语音任务持久保存 requestId 和上游任务编号。回包丢失后先查询原任务，网络重试沿用原编号；明确失败后的人工重试才创建新任务。每用户最多两个语音请求同时处理，客户端按消息顺序生成语音。

## 网关配置

密钥仅保存在 services/gateway/.env，本轮已使用用户 key.txt 中的中转信息配置本地环境。key.txt 已加入忽略规则，源码、APK、交付归档均不包含真实密钥。

~~~dotenv
VOICE_API_KEY=<中转密钥>
VOICE_BASE_URL=https://api.lk888.ai/v1
VOICE_TTS_MODEL=doubao-tts-2.0
VOICE_ASR_MODEL=gem-3.8-flash
VOICE_DEFAULT_ID=zh_female_vv_uranus_bigtts
~~~

VOICE_BASE_URL 和 VOICE_API_KEY 同时留空时，语音可复用已保存的陪伴聊天服务。单独更改语音目标但不提供专用密钥时，不会把聊天密钥转发给另一个目标。

中转的转写采用 Gemini 原生音频输入；合成采用 /v1/media/generate 提交豆包任务，再查询 /v1/skills/task-status。该中转不支持常规 /v1/audio/* 路径。

新增接口（均要求账户登录）：

| 接口 | 用途 |
| --- | --- |
| GET /v1/voice/config | 功能状态、音色与录音时长限制 |
| POST /v1/voice/messages/:requestId?durationMs=... | multipart 录音上传、转写、保存原音频 |
| POST /v1/voice/speech | 创建或恢复 AI 合成任务 |
| GET /v1/voice/speech/:requestId | 查询任务并缓存已生成的音频 |
| GET /v1/files/:fileId | 鉴权播放原录音或生成音频 |

## 2026-10-15 语音请求与聊天正文协作修复

语音气泡已经出现却说“发不了语音”，是回复正文中的能力判断出了错：陪伴模型先生成文字，客户端再将这段文字合成语音，错误说明也被读了出来。现已在所有陪伴人设最终输出规则里说明应用的语音能力，不沿用历史中“只能打字”的判断，不虚称音频已经送达。用户要求语音是回复形式，正文先回应用户真正表达的内容；auto / voice / text 偏好继续由应用处理。

文字生硬的另一来源是人设中戏剧化的嫌弃、反问和冲突示例被套用到普通亲近与分享。最终版本为 Agent29：所有人设增加按字面善意接话的规则，不凭空猜测动机、凭钟点评判用户是否有资格累，或靠每轮先刺一句表现性格。未编辑的内置沈知意提示词在运行时适配为手机口语，保留背景、骄傲、慢热和嘴硬心软；精确匹配原内置提示词才适配，用户编辑过的全文保持原样，已保存资料、长相和记忆均不改写。

真实模型的最终五组独立样本通过语义检查，覆盖默认角色、含旧错误拒绝的自定义角色、想念的不同说法、下班分享和低落倾诉。样本包括“好久没听你声音了，有点想你” → “嗯 你这么说我还挺高兴的”，“今天终于下班了” → “总算熬到下班了”。结果说明本次场景已有改善，不保证所有未来对话都符合全部风格偏好。先前仅自动检查通过但语义未通过的结果均保留为 needs-revision；候选第三、四轮未部署。
