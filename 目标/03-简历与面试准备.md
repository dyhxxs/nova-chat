## 三、90 秒项目介绍

可以按下面顺序回答：

1. Nova Chat 解决什么问题：让用户通过移动端使用不同模型，同时能够自托管并保存自己的资料。
2. 系统怎么工作：移动端负责交互，网关负责认证、权限、模型路由、资料和任务状态，第三方模型服务只由网关访问。
3. 最难的地方：流式请求取消和断线恢复、多用户权限隔离、第三方 Key 保护、知识库引用和拒答。
4. 你如何验证：类型检查、自动化测试、构建验证、知识库评测和部署演示。
5. 当前限制：模型能力依赖上游服务，当前知识库是词法 baseline 与 BM25 实验，生产规模的负载、成本和多副本部署数据还需要补充。

## 四、常见面试问题

### 1. 为什么要设计 Gateway，而不是让 App 直接调用模型？

因为模型 API Key、统一模型配置、权限、限流、审计和多用户隔离都需要由服务端控制。移动端直连会暴露密钥，也无法可靠管理不同用户的请求。

### 2. 为什么同时使用 WebSocket 和 REST？

WebSocket 适合流式生成和取消操作，REST 适合健康检查、登录、配置、上传和在 WebSocket 握手失败时提供 fallback。两者承担不同职责。

### 3. 如何防止断线后重复生成和重复计费？

为请求维护稳定的 request ID 和服务端任务状态，在已经开始生成后不盲目自动重试；重复 request ID 需要返回已有状态或拒绝冲突请求。

### 4. 如何保证用户不能读取别人的资料？

所有资料查询、修改、删除和下载都必须同时使用当前认证用户 ID 和资源 ID 查询，不能只根据资源 ID 查询；同时用测试验证跨用户访问被拒绝。

### 5. 知识库为什么不能只依赖大模型？

大模型本身不知道用户上传的私有资料，也可能产生无法验证的内容。检索系统负责找资料，回答中保留来源，找不到依据时拒答，才能提高可验证性。

### 6. 为什么需要评测集？

没有评测集就只能凭感觉修改检索和提示词，无法判断改动是变好还是变坏。评测集还可以记录失败案例，帮助比较不同模型和检索策略。

### 7. 当前项目有什么不足？

当前主要不足是还没有向量或混合检索证据，生产规模的性能、成本和恢复数据不足，部分功能依赖第三方模型服务；Docker、反向代理、真机和备份恢复仍需在目标环境完成验收。明确说出限制比声称项目完美更可信。

## 五、面试前必须真正掌握的内容

- 能画出移动端、网关、数据库和模型服务之间的数据流；
- 能解释一次聊天请求从输入到完成的完整生命周期；
- 能解释 Session、权限和 API Key 的保存方式；
- 能说明一次失败请求如何清理状态；
- 能说明知识库如何切分、检索、引用和拒答；
- 能实际启动项目，而不是只看代码；
- 能展示至少一个自动化测试；
- 能展示一次评测失败案例和你的修复过程；
- 能区分“代码已经实现”和“已经在线上验证”；
- 不夸大没有证据的用户量、准确率和生产能力。
