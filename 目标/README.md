# Nova Chat 求职项目开发目标

## 这份目录的用途

本目录是 `E:\gptapp` 后续求职版项目的开发目标和验收标准。新项目从原项目中提取和完善，不追求继续堆功能，而是把已有能力整理成一个面试官可以快速理解、运行和验证的完整项目。

## 项目最终定位

**Nova Chat：支持多模型、知识库和多模态能力的可自托管 AI 助手平台。**

目标岗位默认是：

- AI 应用工程师；
- AI 后端工程师；
- 全栈 AI 工程师；
- 具备移动端能力的后端工程师。

“AI 陪伴”是产品场景之一，不作为唯一卖点。求职展示重点放在：

- 多模型统一接入；
- 移动端到服务端网关的完整架构；
- WebSocket 流式生成和 REST fallback；
- 用户、管理员、Session 和权限控制；
- API Key 加密保存；
- 知识库和带来源回答；
- 文件、图片、语音等多模态任务；
- 限流、并发控制、错误脱敏和自托管部署；
- 测试、评测和可复现运行。

## 当前基线

原项目已经具备比较完整的工程基础：

- Expo / React Native 移动端；
- Fastify 网关；
- TypeScript 共享协议；
- SQLite 数据库；
- 多模型服务配置；
- 账户和权限系统；
- 知识库、附件、图片和语音能力；
- Docker 部署文档；
- 完整的类型检查、测试和 lint 流程。

当前基线验证结果应以实际命令为准：

```powershell
npm ci
npm run verify
npm run build
```

当前已经补齐的求职版基础包括：

- 合成知识库评测集、JSON/Markdown 报告，以及 lexical 与 FTS5 BM25 的可复现实验对比；
- 请求 ID、健康/就绪探针、可选 Prometheus 指标、登录限流、日志脱敏和统一错误响应；
- 优雅下线流程和仅管理员可访问的分页审计日志；
- 项目 README、部署说明、技术案例、安全说明和演示脚本。

仍需通过真实环境验证或继续迭代的部分是：

1. 当前检索仍是词法 baseline 与 BM25 实验，没有向量或混合检索证据；
2. Docker Hub、反向代理 HTTPS/WSS、真实模型服务、Android/iOS 真机和备份恢复还需要实际演练；
3. 工作区原有调试截图、XML 和临时文档仍需在独立发布分支中整理；
4. 生产规模负载、成本和多副本部署数据尚未建立。

## 最终演示主线

演示只围绕下面一条流程展开：

```text
用户注册
  -> 管理员配置模型服务
  -> 用户上传个人资料
  -> 知识库建立索引
  -> 用户提出问题
  -> 系统检索资料并返回带来源的回答
  -> 展示流式生成、权限控制、错误处理和历史记录
```

角色照片、语音、图片生成等能力作为扩展能力展示，不要让它们分散主线。

## 重要原则

- 不要继续无目标地增加功能；
- 每增加一个 AI 能力，都必须有测试数据和评测指标；
- 每增加一个后端能力，都必须有错误处理或自动化测试；
- 先完成可运行的最小版本，再优化效果；
- 不把合成数据包装成真实企业数据；
- 不在 README 中宣称没有证据的生产级指标；
- 不把 API Key、Token、数据库、`.env` 或运行数据提交到版本库；
- 保留原项目作为备份，新项目使用干净分支或干净目录。

## 开发顺序

1. 先整理项目定位和仓库；
2. 再建立知识库评测集；
3. 再改进检索效果；
4. 再补安全、稳定性和部署验收；
5. 最后整理 README、演示视频、简历和面试材料。
